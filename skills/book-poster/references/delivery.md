# 交付、接续与归档

用于交付预览/母版、更新任务状态，以及用户请求的参考卡和归档。局部修改只执行对应检查，不强制为每张草图制作完整档案包。

## 确认交付的是当前作品

核对文件实际存在、可读取、书名/作者准确、像素尺寸与画面一致，显示实际交付图并提供绝对路径。全图和预期展示尺寸都看过，必要时附细节图；小字在手机缩略图不可读不能仅靠“已加字号”判通过。

原生文件按 [photocraft.md](photocraft.md) 重开检查；文字、矢量轮廓、图像和嵌入对象的编辑能力据实说明。像素尺寸、色彩模式与适用用途按实际报告。印刷尺寸、出血和输出条件未明确时，不笼统称印刷级；有实体印刷需求再核尺寸、有效分辨率及所需色彩/导出条件。放大或修改 DPI 标签不代表增加原始细节。

分别记录：制作完成、技术检查、设计判断、用户认可。技术通过不替代审美结论，未解决的主要问题写在交付说明中。

## 一份当前记录，保留版本历史

沿用 task.json 或现有等价记录，不另建重复状态表。当前摘要至少能确定：
- 当前阶段、用户最近原话及本轮授权、已选路线。
- 当前预览与原生母版（如有）、实际制作方法与输出规格。
- 已实现/未解决的主要问题、技术检查范围、用户认可依据和下一步。

老稿的信息保存在版本历史，顶层当前摘要更新到本次交付。历史字段与当前文件冲突时核对实际文件和最新授权；无法确定则保留不确定性，不用较新的时间戳冒充已选定稿。

研究、来源、参考、素材、提示词（确有生成时）、原稿与修订稿留在任务目录。记录用户提供的原设计/草图与关键决定、助手提出的方案及实际制作修改；复盘时据此区分共同设计成效与独立能力。取图 manifest 保持快照，使用账本按 [library.md](library.md) 记录事实，不代替用户选择。

## 参考卡与作品归档

用户要求或约定交付包含参考卡时，从实际成品提取色卡、字体及标志性字形，附原书、参考作品/素材和数据来源。呈现深度服从使用场景；定制字形与可用字体区分，卡片不新增成图中没有的规格。

用户要求归档时，在指定资料库建立作品档案，保存认可的 PNG、可用母版、来源与简要修改说明，以及已约定的参考卡。核对复制后的内容与文件一致性，保留历史文件。自制作品档案与真实海报参考库分开；照片/图表等任务素材留在任务或作品档案，不自动扩充参考案例库。上传、发布和 Git 推送遵从对应授权，不由本模块自动执行。

值得复用的制作经验写在本次复盘中：原问题、改动、可见改善与代价、适用条件。未获更新 Skill 或长期记忆的授权时，不自动把某次版式、颜色或用户选择写成通用规则。
