# 从探索到选图

用于开放探索的首轮参考选择，或分析用户指定的真实海报。延续已选方案只补查本次变化需要的部分。用户指定参考时先直接看图分析下节的迁移关系；只有缺少依据或用户要求比较时才扩大检索。CLI、词表和暂存方法见 [library.md](library.md)。不要求增加用户对话轮次。

## 参考怎样组织真实信息

选主要依据前看清：第一眼焦点、尺度与裁切、主轴与留白、字图关系，以及数字、行列、颜色、间隔、空缺和文字块原本承担的内容。记录它为什么形成这种版面，不只描述外观。

迁移时写清“原内容与组织规则 → 本书可支持的内容 → 保留的关系与必要变化”。可以借组织方法而改变行列数、密度或尺度；若没有成立的对应数据，改为明确的非数据图形，或选更适合的结构，不编造日期、比例和活动填满版面。数据核验与制作见 [production.md](production.md)。

流派提供方法，具体作品提供可观察的关系。每条路线区分历史归属、有据影响和视觉近似，最终检查构图如何实现本书命题；流派标签不同或不同参考 ID 不足以证明两条路线实际不同。

## 1. 让书籍提出问题

从已核阅读材料写下内容关系、具体物象/场景、观看感受；区分原文、书评与设计解释。先保留几种可能的画面机制，再确定最终几何形状、字体套路和流派。若书评存在不同解释，可用它们形成不同的查询入口。

查询分开尝试：内容概念和关系；潜在物象/媒介；不同视觉路线或手法。后两者用来探索，不是先指定成品。例如“代际记忆”既可检索 memory/time，也应比较人物、手写、层叠、物件残留等可能性，具体选法仍由本书证据与看图决定。例子不是固定查询包。

自由词未命中时保留这个缺口，尝试近义表达、实际受控标签或从宽的视觉类别。不要将“只命中摄影”解释为“找到最适合某种哲学理论的作品”。`--match all` 与筛选用于真正硬条件，不为凑数量悄悄解除它们。

## 2. 扩大所见，再收敛

不同查询的结果合并去重。起始预算约 18–30 个候选、12–18 张实际看图；若高度相关的图少，报告缺口并按需联网补充。用户已指定图或明确时间限制时缩小探索；复杂题材可扩大。不用“达到数量”代替内容判断。

先浏览原图或已有预览，记下实际看到的 ID；最终四张及主构图参考再看完整尺寸和案例分析。无需先制作集合图，也不必把所有内部候选展示给用户。最终展示仍用真实原图。

如果候选几乎全来自同一视觉路线，检查这是书籍/用户硬要求造成，还是查询词过早限定了形式；后者应补一次不同入口的探索。前几张已足够漂亮，不是停止比较的充分依据。

## 3. 近期使用与批次比较

已有项目使用账本时，检索带上账本和本任务稳定 seed（如任务 ID）；无账本正常开始。seed 在同一轮保持一致，不能不断换 seed 直到搜到预想作品。排序的上下文分数仅在同等相关性候选间作取舍提示。

多本书或多代理任务将其他分支已拟用 ID 作为 `--batch-ids` 复查，同时人工比较：焦点位置、主体比例、裁切、主轴线、留白形状、图文关系、观看顺序。构图标签重叠只是粗提示，视觉比较才能判断是否是同一骨架。

近期作品没有禁用期。若重新使用，记录它相对本轮其他已看候选的具体优势；用户指定的参考优先。反过来，不能仅为降低重合率而选更弱或不相关的图。主体换成另一物件、作者不同、标签不同，都不足以单独证明方案有差异。

## 4. 留下能复查的证据

在任务目录保存一份 `selection-evidence.json`（或已有等价记录），不在多份文件重复维护当前决定。以下内容按实际执行的探索记录；用户指定参考而未检索时，仅记录提供来源、实看与迁移判断，查询、四图和淘汰者等记为不适用，不为补字段启动检索：

- 每条查询的原词、seed、筛选、账本路径/窗口、本批 ID、实际结果（含命中与缺失词）；
- 去重候选 ID、实际查看 ID，以及实际数量；
- 入选四图、主要被淘汰替代者及简短视觉理由；
- 每条路线借鉴的具体构图关系、书籍特有依据和换书名检查；
- 与近期/同批作品的关系，保留重复或改选的原因；
- 限制：少看了什么、哪里只靠部分命中、哪些尚未生成。

参考展示后将 shown_ids 记入使用事件；used_ids 的既有生图输入语义及原生制作的记录方式见 library.md。它们都是使用事实，不是用户喜欢。所有并行分支先输出任务事件，由协调者单次归并写账本；分支不抢写共享文件。更新事实用新的 event_id，同一事件重试保持内容完全一致。账本记录不能替代 task.json 中用户的当前决定。

验收范围分别报告：检索/取图是否正常、选图是否经过比较、生成画面是否成立、用户是否认可。更多不同 ID 只证明曝光变化，不证明审美提高。
